## 무엇을 위한 문서인가

한국에서 사내 시스템이나 일반 웹 서비스를 만드는 개발자가 **기능을 구현하는 시점에** 확인해야 할 개인정보 보호법·정보보안 요구사항을 정리했습니다. 법률 요약집이 아니라 설계 문서와 코드 리뷰에서 바로 참고하는 기술문서를 목표로 합니다.

:::caution[법률 자문이 아닙니다]
이 가이드는 법률 자문이나 적합성 인증이 아닙니다. 최종 판단은 공식 원문과 사내 법무·개인정보 보호책임자의 검토를 거치세요.
:::

## 문서 구성

모든 주제 문서는 같은 순서로 씁니다.

1. **한 문장 결론**: 가장 먼저 알아야 할 것
2. **적용 조건과 예외**
3. **실제 법적 근거**: 조문을 직접 인용
4. **개발자용 실무 해설**
5. **권장 설계** / 6. **위험한 설계**
7. **Python/TypeScript 구현 예제**
8. **개발 체크리스트**
9. **공식 원문 링크와 확인일**

문서 끝에는 frontmatter에서 자동으로 만든 **근거 구분표**, **공식 원문 링크**, **관련 문서**가 붙습니다.

## 상태 표시 읽는 법

| 표시 | 의미 |
| --- | --- |
| <span class="badge badge-draft">작성 중</span> | 초안. 내용이 크게 바뀔 수 있음 |
| <span class="badge badge-review-required">검토 필요</span> | 공식 원문과 대조했지만 법률 전문가 검토는 거치지 않음 |
| <span class="badge badge-reviewed">검토 완료</span> | 지정된 검토자가 승인함(검토자·검토일 표시) |
| `review-required` | 해당 문장이나 근거를 공식 원문으로 확인하지 못함 |

날짜는 세 가지를 구분합니다.

- **시행일**: 법령이 효력을 갖는 날. 시행 예정 규정은 현재 의무로 쓰지 않습니다.
- **발행일**: 안내서·고시가 공표된 날.
- **공식 원문 확인일**(`lastVerified`): 이 문서의 서술을 원문과 마지막으로 대조한 날. 페이지 하단의 "마지막 업데이트"(파일 수정일)와는 다릅니다.

## 근거 종류

| 종류 | 법적 성격 | 예 |
| --- | --- | --- |
| <span class="kind kind-binding">법률·시행령·고시</span> | 법적 의무 | 개인정보 보호법, 시행령, 개인정보의 안전성 확보조치 기준 |
| <span class="kind kind-advisory">행정기관 안내서</span> | 해석·권고 | 개인정보 처리 통합 안내서, 생성형 AI 개인정보 처리 안내서 |
| <span class="kind kind-advisory">기술 표준</span> | 권고 | OWASP ASVS 5.0 |
| <span class="kind kind-advisory">프로젝트 권장사항</span> | 권고 | 이 가이드가 제안하는 설계 |
